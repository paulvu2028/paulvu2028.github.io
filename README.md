# personal-portfolio-project

Personal portfolio site for Paul Vu, software engineer in Auckland, New Zealand. Static site built with Astro 5 and Tailwind CSS 4: a one-page home with numbered sections, a projects index and detail pages, a print-optimized resume, and a styled 404. Dark theme, emerald accent, no external runtime resources (fonts are bundled from Fontsource).

## Quick start

Requires Node 22.12+ (Node 24 recommended).

```sh
npm install        # install dependencies
npm run dev        # dev server at localhost:4321
npm run build      # production build to ./dist/
npm run preview    # preview the production build locally
npm run check      # typecheck .astro and .ts files (astro check)
```

## Editing content

All site content lives in typed data files under `src/data/`, one file per content type. You should not need to touch components or pages to change what the site says.

| File | Content |
| --- | --- |
| `src/data/profile.ts` | Name, role, location, email, socials, hero copy |
| `src/data/experience.ts` | Experience timeline entries |
| `src/data/education.ts` | Education entries for the resume |
| `src/data/skills.ts` | Skill groups and chips |
| `src/data/projects.ts` | Projects (copy, tags, links, images) |
| `src/data/testimonials.ts` | Quotes for the home page |

Copy that is fixed page furniture (About paragraphs, AI-first points, Contact copy) lives directly in the matching component under `src/components/`.

Project images are imported in `src/data/projects.ts` from `src/assets/projects/`. By convention, `images[0]` is the card image and `images[1..]` are detail-page images. Projects with no images get a CSS-only visual instead.

## Adding a project

1. Drop the images into `src/assets/projects/` (optional).
2. Append an entry to the `projects` array in `src/data/projects.ts`. Give it a unique `slug`, set `status` to `"Active"` or `"Shipped"`, set `featured` to `true` to show it on the home page, and set `sort` to control ordering.
3. Import the images at the top of the file and list them in `images`.

The detail page at `/projects/<slug>/` is generated automatically from `getStaticPaths`. No routing changes needed.

## Deploying

The site is static output, so GitHub Pages needs no adapter changes.

The project is named `personal-portfolio-project`, but the GitHub repo is deliberately named `paulvu2028.github.io` so the site hosts at the Pages root URL.

Deployment is handled by the GitHub Actions workflow in `.github/workflows/deploy.yml`. Every push to `main` rebuilds and redeploys the site automatically, and the workflow can also be run manually from the Actions tab.

One-time setup: in the repo settings, GitHub Pages must have Source set to "GitHub Actions" (build type `workflow`), not deploy from a branch. `dist/` is gitignored and never committed, so a branch deploy has no built files to serve.

The site then hosts at `https://paulvu2028.github.io`.

The sitemap is generated by `@astrojs/sitemap` using the `site` value in `astro.config.mjs`, which matches that URL.
